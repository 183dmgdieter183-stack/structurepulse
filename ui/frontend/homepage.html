The Science

Architecture has
a measurable signal.

The Higuchi Fractal Dimension, originally designed for EEG brain signal analysis, detects structural complexity in any time series — including the complexity distribution of a codebase.

Applied to code: below 1.7 means modules are too homogeneous — no specialization, no meaningful architecture. Above 1.9 means one module dominates and complexity is uncontrolled. The band 1.7 – 1.9 is where maintainable, well-differentiated systems live.

StructurePulse doesn't just measure FD. It combines it with entropy, coupling density, cycle detection, and test topology into a single Structural Health Index (SHI).

Rigid (FD < 1.7)
Optimal (1.7 – 1.9)
Chaotic (FD > 1.9)
What we measure

Five signals.
One verdict.

FD
Fractal Dimension
Higuchi complexity of the module complexity series. Measures whether your codebase has meaningful structural differentiation.
target: 1.7 – 1.9
SHI
Structural Health Index
Weighted composite of all five signals. The single number that answers: "Is this codebase maintainable?"
target: ≥ 0.80
ρ
Coupling Density
Import-graph edge density normalized by module count. High coupling means one change propagates everywhere.
target: < 0.40
∅

target: 0
Process

How it
works.

SHI 0.847 — HEALTHY
1

Parse

AST-based parser extracts nodes, edges, and import lines from Python and TypeScript. Boilerplate files are tagged and excluded from complexity calculations automatically.

2

Build the graph

Module dependencies become a directed graph. Cycles are detected via depth-first search. Each cycle node is annotated with the exact import line number.

3

Compute metrics

Higuchi FD is calculated over the complexity series. Coupling density is derived from edge count normalized by module count. Entropy and test topology complete the picture.

4

Detect smells

Four heuristics cross-reference file names against graph topology — Hidden Hubs, Layer Inversions, Responsibility Leaks, Dead Weight — without any LLM or external API.

5

Explain

The --explain flag translates every metric deviation into a concrete refactoring suggestion with the exact file and line responsible.

Role-Inconsistency Detection

The graph never lies.
Names do.

StructurePulse cross-references what a file is called against how it actually behaves in the dependency graph. No LLM. No heuristics trained on your codebase. Pure topology.

H1 — HIDDEN HUB
God Object
A file named utils.py or helpers.py that is imported by more than 40% of the codebase — or has coupling above 0.35 — has grown into a hidden core that violates its own name.
utils.py → imported by 22/34 modules (65%)
H2 — LAYER INVERSION
Broken Architecture
A data or model module that imports from a controller or service module reverses the dependency arrow that clean architecture requires. Almost never intentional.
user_model.py → imports user_service.py
H3 — RESPONSIBILITY LEAK
Config Calling Logic
A configuration file that imports project-internal business logic has leaked responsibility. Config is data. It should not orchestrate anything.
config.py → imports app.py, services.py
H4 — DEAD WEIGHT
Anemic Service
A file named *_service.py with defined functions but zero outgoing imports does nothing real. Either it needs a repository to call, or it should be removed.
payment_service.py → 3 functions, 0 imports
Enforcement

Architecture as
a gate,
not an afterthought.

Drop StructurePulse into any CI pipeline. A PR that introduces a dependency cycle or degrades SHI below your threshold fails the build — before it reaches main.

✓ Exit code 0 — architecture healthy
✗ Exit code 1 — condition violated
→ Pre-commit hook available
YAML .github/workflows/structurepulse.yml 
# Architecture Gate — blocks degrading PRs
name: Architecture Gate
on: [pull_request]

jobs:
  architecture:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }

      - run: pip install structurepulse

      - name: Scan architecture
        run: sp scan . \
          --exclude "tests/" \
          --fail-on cycles \
          --fail-on "shi<0.7" \
          --fail-on inconsistencies
BASH pre-commit hook 
# Install once, enforces on every commit
sp install-hook --path .
